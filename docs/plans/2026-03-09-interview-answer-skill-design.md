# 面试题 Markdown 生成 Skill 设计

## 目标

在当前仓库内提供一个私有 skill，仅在用户明确点名时触发。skill 读取指定 Markdown 文件，将文件名视为面试题，生成适合真实面试口述场景的精炼答案，并在底部补充面试官高频追问。

## 适用范围

- 默认处理 `面试准备/` 下的 Markdown 文件。
- 允许用户显式指定 `PRD/` 或其他目录下的单个 Markdown 文件。
- 不面向通用仓库，不做跨项目抽象。

## 触发方式

- 仅在用户明确点名该 skill 时使用。
- 不做隐式触发，避免在普通文档整理任务中误用。

## 关键规则

### 文件处理

- 目标文件为空时：直接写入生成内容。
- 目标文件已有内容时：禁止直接改写，必须先输出“拟新增/拟修改预览”，等待用户确认。
- 默认不批量处理多个文件，除非用户明确要求。

### 输出结构

每个题目文件统一采用以下结构：

1. `## 回答`
2. `## 面试官追问`
3. `## 可举的项目例子`
4. `## 易踩坑`

其中：

- `回答` 部分优先给出 30~90 秒可口述版本。
- `面试官追问` 追加 3~5 组常见深挖问题，并给出简洁回答。
- `可举的项目例子` 优先写可迁移的项目讲法，不强编不存在的经历。
- `易踩坑` 用来提醒面试中容易答偏、答大、答空的问题。

## 文风约束

- 面向真实面试口述，不写教材式长段定义。
- 结论前置，优先“是什么 / 为什么 / 怎么做 / 取舍”。
- 以短句、要点化表达为主，避免冗长铺垫。
- 默认回答控制在 4~8 个要点内，能在 1 分钟左右说完。
- 追问答案每条控制在 2~4 句，可继续展开，但首版必须精炼。

## 特殊题型处理

- 对于 `自我介绍`、`项目亮点` 这类强依赖个人背景的题目，先向用户补问 1 个最关键上下文，再生成内容。
- 对于偏原理题，优先输出“定义 + 场景 + 优缺点 + 落地经验”。
- 对于偏工程题，优先输出“问题背景 + 方案 + 取舍 + 指标结果”。

## 建议目录

- Skill 目录：`.codex/skills/interview-answer-writer/`
- 主文件：`.codex/skills/interview-answer-writer/SKILL.md`
- 风格参考：`.codex/skills/interview-answer-writer/references/style-guide.md`
- UI 元数据：`.codex/skills/interview-answer-writer/agents/openai.yaml`

## 验证标准

- skill 描述能明确表达“仅显式调用、仅服务当前仓库、生成面试题答案”。
- 对空文件和非空文件的行为清晰且不冲突。
- 生成结果在口语化、精炼程度上稳定，避免出现百科式答案。
- `quick_validate.py` 校验通过。

## 调用示例

- 使用 `$interview-answer-writer`，为 `面试准备/monorepo 架构的优势是什么？.md` 生成完整答案。
- 使用 `$interview-answer-writer`，先预览你会如何补充 `面试准备/自我介绍.md`，不要直接修改。
- 使用 `$interview-answer-writer`，继续为当前题目补 3 轮面试官追问，并保持口语化、精炼。

# HTTP 缓存机制详解

## 1. 什么是 HTTP 缓存？

当我们打开一个页面时，浏览器会向服务端发起许多次请求。例如打开百度首页，发起了 HTML、各种图片、JS、CSS 等资源共 101 次请求。这里面很多资源并不会频繁变化，如果每次打开页面都重新下载，会造成严重的资源浪费。

**浏览器缓存**（也称为 **HTTP 缓存**）是指浏览器本地缓存了 HTTP 响应，以便后续复用，减少向服务端的请求。

### 缓存的作用

- **提升加载速度**：对于静态资源（图片、JS、CSS 等），直接从本地读取，网页加载飞快。
- **减轻服务端压力**：减少冗余请求，降低带宽消耗和服务器负载。

---

## 2. 缓存的存储位置

缓存主要存储在**内存**和**磁盘**上，具体存储策略由浏览器决定。

- **内存缓存 (from memory cache)**：
  - 读取速度最快。
  - 进程结束（如关闭标签页）后内存即释放。
- **磁盘缓存 (from disk cache)**：
  - 读取速度稍慢（但依然很快）。
  - 容量大，由于存储在磁盘中，可以长久保存。

---

## 3. 缓存规则：强缓存与协商缓存

浏览器查找缓存的顺序是：**先查找强缓存，若失效再进行协商缓存。**

### 强缓存 (Strong Cache)

浏览器自行决定的缓存机制，**不需要连接服务端**。如果强缓存命中且在有效期内（Status Code: 200 from cache），浏览器直接使用本地资源。

- **核心字段**：`Cache-Control` (HTTP/1.1)

#### Cache-Control 常用指令

| 指令                | 说明                                                                        |
| :------------------ | :-------------------------------------------------------------------------- |
| **max-age=N**       | 缓存最大周期（秒）。超过此时间则认为过期（如 `max-age=3600` 表示 1 小时）。 |
| **no-cache**        | **强制协商缓存**。不会直接使用本地缓存，必须每次都询问服务器是否有更新。    |
| **no-store**        | **禁用缓存**。不存储任何响应内容到本地。                                    |
| **public**          | 响应可以被任何中间代理（如 CDN）缓存。                                      |
| **private**         | 响应只能被客户端浏览器缓存，不允许中间代理缓存。                            |
| **must-revalidate** | 一旦资源过期，必须向服务器验证。                                            |
| **immutable**       | 资源内容永远不会改变，告诉浏览器即使刷新也不要发请求。                      |

---

### 协商缓存 (Conditional Cache)

当强缓存失效或配置为 `no-cache` 时，浏览器会连接服务端，询问资源是否有变化。

- **如果资源未变**：服务器返回 **304 Not Modified**（不包含 Body），浏览器继续使用本地缓存。
- **如果资源已变**：服务器返回 **200 OK** + 新的资源内容，浏览器更新缓存。

#### 协商缓存的核心字段

##### 1. Last-Modified (最后修改时间)

- **原理**：
  - 第一次请求：服务端返回 `Last-Modified`。
  - 再次请求：浏览器发送 `If-Modified-Since`（值为上次的修改时间）。
  - 服务端判断：如果文件未更新，返回 304。

```http
// 响应头
Last-Modified: Tue, 22 Feb 2022 22:00:00 GMT

// 请求头（协商时）
If-Modified-Since: Tue, 22 Feb 2022 22:00:00 GMT
```

##### 2. ETag (资源唯一标签)

- **原理**：`ETag` 是文件内容的唯一标识符（类似指纹或哈希值）。
  - 第一次请求：服务端返回 `ETag`。
  - 再次请求：浏览器发送 `If-None-Match`。
  - 服务端判断：如果 ETag 匹配，返回 304。

```http
// 响应头
ETag: "639b0692-72"

// 请求头（协商时）
If-None-Match: "639b0692-72"
```

> **注意**：`ETag` 的优先级高于 `Last-Modified`。因为它更精确（解决 1 秒内多次修改或内容没变但修改时间变了的问题）。

## 4. 实践建议

### 最佳实践

1. **静态资源 (JS/CSS/图片)**：设置长效强缓存。
   - `Cache-Control: max-age=31536000` (1年)。
   - 通过文件名哈希（如 `app.a1b2c3.js`）来控制更新。
2. **HTML 文档**：推荐强制协商缓存。
   - `Cache-Control: no-cache`。确保每次都能获取到最新的入口文件。
3. **混合使用**：`Last-Modified` 和 `ETag` 通常同时开启作为双重保险。

### 如何清除缓存

- **强制刷新**：`Shift + F5` (Windows) 或 `Cmd + Shift + R` (Mac)。
- **调试模式**：在开发者工具的 Network 面板勾选 `Disable cache`（停用缓存）。
- **手动清除**：在浏览器设置中清除浏览数据。

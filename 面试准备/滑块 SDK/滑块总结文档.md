## 一句话定位

这是一个企业级滑块验证码前端 SDK。它表面上是一个验证码组件，但本质上做的是一整条前端反自动化验证链路：把设备指纹、滑动轨迹、会话信息和动态加密整合起来，再以 SDK 的形式交付给业务方快速接入。

## 更像前端面试回答的 60–90 秒口语稿

我最近做的一个比较有代表性的项目，是一个滑块验证码前端 SDK。这个项目对外看起来像一个前端组件，但我理解它的核心价值其实不是 UI，而是把验证码验证流程做成一条完整的前端安全链路。

具体来说，用户打开验证码后，前端会先生成设备指纹，然后调用初始化接口拿到本次会话的盐值、时间戳和请求标识。用户拖动滑块时，我们会采集轨迹点、滑动时长以及轨迹的速度和平滑度特征；等用户完成滑动后，再把坐标和轨迹数据一起，用“设备指纹 + salt + timestamp + requestId”派生出来的动态密钥做加密，然后把密文发给后端校验。

从工程实现上，我把核心能力拆成了几个包：SDK 主包负责 UI、生命周期和请求链路；`captcha-core` 负责核心加密逻辑选择；现代浏览器优先走 `WASM + Web Crypto`，低版本浏览器自动降级到 `JS + CryptoJS`。项目是一个 monorepo，里面还带了示例应用，方便调试、演示和业务接入。这个项目比较能体现我在前端 SDK 工程化、浏览器兼容、以及前端安全链路设计上的能力。

## 这个项目最值得讲的技术亮点

### 1. 它不是单纯的 UI 组件，而是一个前端安全 SDK

很多验证码项目只会停留在“把滑块做出来”，但这个项目真正的重点是把前端采集到的设备和行为信息，和服务端的会话信息绑定起来，构成一条更完整的验证链路。

### 2. 做了设备指纹 + 轨迹 + 动态密钥的组合校验

不是只看用户有没有把滑块拖到终点，而是把设备指纹、轨迹行为、一次性会话数据和加密链路绑定在一起，提高自动化脚本模拟的成本。

### 3. 做了两层降级策略

- 第一层是核心实现层：优先走 `WASM`，失败时降级到 `JS`
- 第二层是加密能力层：优先走 `Web Crypto API`，不支持时再降级到 `CryptoJS`

这让项目在性能、安全性和浏览器兼容性之间找到了一种比较平衡的方案。

### 4. 按 SDK 的方式封装，业务接入成本低

业务只需要调用初始化方法，传入容器、语言、超时时间和回调函数，就能在页面里使用验证码能力。对业务方来说，接入成本很低，调用方式也比较稳定。

### 5. 工程化做得比较完整

项目采用 monorepo 管理，区分 SDK 主包、核心逻辑包、加密工具包和 demo 应用；构建上有分包、混淆、按环境输出和版本目录，比较符合一个可交付前端 SDK 的形态。

## 面试里很可能会被追问的 7 个问题

### 1. 你为什么说这不是一个普通的滑块组件？

因为它的核心价值不是“能拖动”，而是“能验证”。真正的技术点在于把前端采集到的设备指纹和滑动行为数据，与后端下发的会话信息绑定，再通过动态密钥加密后提交校验，所以它更像一个安全 SDK，而不只是一个 UI 组件。

### 2. 为什么要引入设备指纹？

设备指纹不是用来单独决定通过或失败的，而是作为风险判断和会话绑定的一部分。这样可以减少重放攻击和跨设备伪造的风险，也能给后端提供更多风控维度。

### 3. 为什么要记录轨迹，而不是只校验最终坐标？

如果只看最终坐标，脚本很容易直接构造结果。轨迹里能体现速度变化、停顿、平滑度这些行为特征，这些特征更接近真实用户操作，也更适合和后端风控一起配合做识别。

### 4. 为什么要做动态密钥？

因为如果前端每次都用固定规则或者固定密钥去传验证数据，那只要被逆向一次，后面就很容易复用。动态密钥把设备指纹、salt、timestamp 和 requestId 绑定到一次会话里，可以明显提高重放和伪造的难度。

### 5. 为什么要做 WASM 和 JS 两套实现？

WASM 的优势是性能更好，也更适合承载一部分核心逻辑；但浏览器环境非常复杂，不能假设所有场景都支持或都能稳定加载，所以必须保留 JS fallback，才能让 SDK 真正可用。

### 6. 为什么还要再做一层 Web Crypto / CryptoJS 的降级？

因为即使不考虑 WASM，浏览器本身对加密能力的支持也不完全一致。现代浏览器可以直接用原生的 Web Crypto API，性能和安全性都更好；低版本环境则要用 CryptoJS 兜底，这样 SDK 在更多环境里都能工作。

### 7. 你觉得这个项目最能体现你的什么能力？

我会说主要体现了三件事：第一是前端 SDK 的抽象和工程化能力；第二是对浏览器环境差异和兼容性的理解；第三是能够把安全需求拆成前端可执行的技术链路，而不是只停留在业务功能层面。

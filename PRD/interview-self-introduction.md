# 前端资深工程师面试自我介绍准备 PRD

## 1. 背景目标

- **用户背景**：刘加海，9 年前端经验，2 年现任公司资深前端。经历从业务开发到前端基建的职能转变。
- **核心目标**：准备一份能够体现“资深工程师”价值、逻辑清晰、动机合理的面试自我介绍。
- **关键突破点**：
  - 突出 9 年经验的沉淀与厚度。
  - 强调“主动性”：从发现业务痛点到推动基建落地。
  - 优化离职动机：将负面现状转化为对工程规范和职业成长的追求。

## 2. 核心逻辑设计

### 2.1 结构化框架 (Past-Present-Future)

1. **Past (背景)**：姓名、年限、核心技术栈。
2. **Present (近况 & 亮点)**：
   - 业务阶段：统筹能力、跨团队协作。
   - 基建阶段：为什么做（痛点）、做了什么（产出）、效果如何（全员赋能）。
3. **Future (动机)**：为什么看新机会（核心是追求更好的工程文化和发展空间）。

### 2.2 话术升级原则

| 原始描述   | 优化方向              | 建议表达                                                                         |
| :--------- | :-------------------- | :------------------------------------------------------------------------------- |
| 项目流程乱 | 缺乏工程化规范        | “希望加入技术驱动、流程体系成熟的团队，共同沉淀最佳实践。”                       |
| 薪资不满意 | 市场价值对标/寻求增长 | “当前阶段希望在更大规模或更高复杂度的业务场景中，实现技术价值与市场价值的对标。” |
| 领导认可   | 业务影响力/Owner 意识 | “通过对研发效能的观察和闭环建议，完成了从业务骨干到基建负责人的角色升级。”       |

## 3. 功能需求（话术清单）

- [ ] **标准版自我介绍**：适用于各类公司第一轮面试，时长 1.5 - 2 分钟。
- [ ] **基建重点版**：适用于技术深度面试，突出架构、规范、工具链开发。
- [ ] **统筹协作版**：适用于 TL 或架构师面试，突出跨部门推动、过程改进行动力。

## 4. 验收与迭代

1. **自我校验**：朗读流畅度，是否有明显逻辑跳跃。
2. **模拟追问**：针对“基建赋能”的具体数据支撑（如：提效百分比、规范采纳率）。
3. **实时修正**：根据面试反馈，动态调整关于“离职原因”的比重。
